# Staff two-factor is enforced by our staff gate, not by Better Auth

Staff sign in with an emailed magic link and must then enter a time-based code from an authenticator app (TOTP). Better Auth's two-factor plugin only intercepts password, username and phone sign-ins, so a magic-link sign-in would otherwise produce a full session without a second factor. We therefore enforce it ourselves: a staff role counts only for a session that has passed a TOTP check, recorded against that session and checked on every admin request, and a user without two-factor enrolled is sent to enrolment before anything else. We rejected an emailed one-time code as the second factor because it arrives in the same inbox as the magic link, which would make both factors one; SMS was rejected for cost and SIM-swap risk, and passkeys deferred to keep the first release simple (TECH-01).
